## 수집 방법과 판정 범위

1. [다이소몰 건강식품 페이지](https://www.daisomall.co.kr/ds/diy2/C246)를 브라우저로 열고, 상품 카드의 공식 `pdNo` 링크와 이미지 `src`/지연 로딩 `data-src`를 함께 읽었다.
2. 현재 카탈로그 88개와 품번으로 연결했다. 목록에서 썸네일을 찾지 못한 `610911100`, `610911097`, `610911096`은 해당 공식 상품 상세 화면의 첫 번째 대표 썸네일을 확인했다.
3. DOM에서 직접 관찰한 공식 CDN의 `/thumb/` 주소만 사용했다. 주소를 추측하거나 상세 설명·성분표를 잘라 상품 사진으로 대체하지 않았다.
4. 링크 품번, 이미지 파일명의 품번, 표시 상품명과 카탈로그를 연결했다. 파일 형식·실제 이미지 판독·크기·해시·중복 파일 여부를 검사하고, 88개 사진을 검수용 시트에서 직접 확인했다.
5. 브랜드·동일 성분만으로 다른 규격의 사진을 붙이지 않았다. 모델이나 배경이 포함된 사진도 공식 카드의 대표 이미지 그대로 보존했다.

동일 수행자의 자체 확인이며 별도의 독립 제2검수는 아니다. 사진 확인일은 가격·성분표 확인일과 별도로 관리한다.

## 저장 구조

- `data/products/thumbnail-discovery.json`: 관찰한 DOM 이미지 후보와 페이지 출처. 카탈로그 외 상품·중복 카드도 포함한 발견 기록이다.
- `data/products/product-thumbnails.json`: 카탈로그 88개에 한정한 확정 매핑. 품번, 표시명, 공식 이미지·관찰 페이지·상세 URL, 로컬 경로, SHA256, 크기·해상도, 확인일·다운로드 일시, 상태·미확보 이유를 저장한다.
- `data/products/thumbnails/`: 공식 파일 원본. 사진을 변형하거나 재압축하지 않았다.
- SQLite `product_thumbnails`: 제품별 사진 상태와 출처·경로·해시·크기·확인일 및 원장 JSON을 저장한다.
- `products-normalized.json`: 제품별 `thumbnail`로 같은 정보를 담는다(스키마 0.4).
- `frontend/public/product-images/`: 표시 검수 완료 87개만 복사한 화면용 사진.
- `frontend/src/data/products.json`: 사진 경로·공식 출처·확인일을 함께 내보낸다.

DB 재생성 시 사진 원장이 다시 반영된다. 표시 검수 출처 테이블과 사진 정보를 분리해 기존 성분표·OCR 검증 범위를 바꾸지 않았다.

## 화면 처리

공통 `ProductImage` 컴포넌트로 홈, 제품 목록, 예시 결과, 상세, 비교, 대화의 제품 맥락에 사진을 연결한다. `object-fit: contain`으로 세로형 사진을 포함해 전체 이미지를 유지한다. 카드에서는 지연 로딩, 상세에서는 즉시 로딩하고 공간을 미리 확보한다. 실제 이미지 URL은 로컬 자산 경로이므로 방문할 때 다이소몰 CDN을 직접 호출하지 않는다.

상세 사진 아래에 다이소몰 출처와 사진 확인일을 표시한다. 이미지 부재와 로딩 실패는 각각 안내하며 제품명·가격·표시정보·비교 동작을 유지한다. 모바일 대화에서 제품 사진을 숨기는 기존 공간 절약 동작은 유지한다.

## 재수집·재생성·검증

최초 DOM 발견은 브라우저에서 기록한다. 아래 수집기는 해당 기록에 있는 주소만 내려받고, 정상 파일은 URL과 SHA256이 같으면 재사용한다. macOS의 `sips`를 이미지 판독에 사용하며 Python 표준 라이브러리 외 패키지를 설치하지 않는다.

```sh
# 저장소 루트
python3 scripts/collect_product_thumbnails.py
python3 scripts/build_product_database.py
python3 frontend/scripts/export_products.py
python3 scripts/validate_product_database.py
python3 scripts/validate_product_thumbnails.py

cd frontend
npm test
npm run build
```

사진 검증기는 전체 품번, 실제 이미지 헤더·해시·중복, 공식 출처·품번 연결, SQLite와 JSON 일치, 공개 파일 해시, 보류 제품 제외 및 추천 적격 미변경을 검사한다. 실패한 수집은 사유를 남기고 종료 코드를 1로 반환한다. 사진 날짜를 기준으로 성분표나 가격 날짜를 갱신하지 않는다.

# 기능 요구 명세서 — 백엔드 연결판

2026-10-21. Must는 기존 핵심 8개로 유지한다. 실제 사용자 테스트·배포·제출 서류는 서비스 기능과 별도로 진행한다. 기능마다 평가자가 아래 절차를 따라 기대 결과를 확인할 수 있게 한다.

| ID | 기능 | 우선순위 | 구현 | 확인 방법 | 기대 결과 |
|---|---|---|---|---|---|
| M01 | 이용 범위·성인·정보 처리·AI 동의 | Must | 완료 | 추천 또는 AI 진입→동의 미선택 진행→3개 확인 후 진행→하단 철회 | 동의 전 개인 요청 차단. 동의 후 임시 연결. 철회하면 입력 삭제·연결 무효 |
| M02 | 단계별 설문 | Must | 완료 | 관심·식습관·기존 제품·주의조건 입력, 이전 이동, 선택 항목 건너뛰기 | 필수 누락 차단·값 유지·모름과 없음 구분. 예산/제형은 선택 |
| M03 | 근거 검색을 사용하는 AI 대화 | Must | 완료 | 동의→AI 대화→비타민D·식사 질문→인용 펼치기. 제품 상세→이 제품 질문→표시 기능 질문도 확인 | 실제 Gemini가 도구를 선택하고 지원하는 일반 주제는 공식 영양 지식, 상품 질문은 검수 DB를 조회하여 설명·출처 표시. 근거 부족·개인 복용 판단은 구분 안내 |

| M05 | 제품 상세·출처 확인 | Must | 완료 | 목록→마그네슘/칼슘 상세→전체 표시·출처 확인 | DB의 성분·함량·기준·섭취법·주의·사진·관찰일 제공. 없는/보류 품번은404 |
| M06 | 등록 제품 성분 중복 | Must | 완료 | 기존 제품으로 마그네슘30일과10일 제품을 등록해 설문 제출 | 중복 마그네슘 표시, 하루 기준 확정 수량의 합계, 기존 성분과 겹치는 새 후보 제외. 총내용량/단위 불명은 합산 불가 |
| M07 | 두 제품 비교 | Must | 완료 | 제품2개 담기→비교→차이만 보기→세 번째 제품 추가 | 서버에서 가격·성분·기준·섭취법·주의 비교. 세 번째는 교체 확인. 동일 기준이 아닌 함량을 우열로 해석하지 않음 |
| M09 | 제한·정보 부족·실패 안내 | Must | 완료 | 임신/수유 또는 모름 조건, 기존 제품 목록 밖, 연결 실패·AI 오류 | 실제 제한·추가 확인 상태, 해당 단계 복귀·재시도 제공. 정보 미확인을0/안전으로 표시하지 않음 |

M08(다이소 외 대안/상위 제품), 로그인·장기 저장, 재고 조회, 사진 분석 등은 현재 Must와 구현 범위에 넣지 않는다. 실제 평가에서는 각 Must의 확인 방법을 반복하며, 수집 자료·AI 키·서버 기동 상태를 사전에 확인한다.

## 비기능 요구와 구조

- 반응형 UI, 키보드·레이블·오류 상태, 사진 비율 유지.
- 읽기 전용 검수 SQLite, API 입력 검증·동의 게이트·제한된 도구 인자·오류 정규화.
- 키는 서버 환경변수, `.env` Git 제외. 건강 입력·대화 원문 영구 저장 없음. 외부 전송 동의 및 전송 최소화.
- 최초 서버 기동·AI 생성 로딩 구분, 기한·재시도·동시 실행 제한.
- Gemini 모델명·추천 정책 버전·출처 ID로 결과 확인 가능. 단일 샘플 응답속도를 보장 성능으로 주장하지 않음.

시스템: React 화면 → FastAPI → 정책/상품 조회/중복/비교 및 Gemini Agent → 검수 SQLite 검색. Agent와 RAG의 실제 코드 위치·동작은 [API 구조](backend-api.md)에 명시한다.

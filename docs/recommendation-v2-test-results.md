# 추천 정책 v2 로컬 검증

> 최신 관심 분류 `2026-10-23.3`: 추천 관심 분야를 일상의 활력·뼈·근육 건강·장 건강·혈당 관리·다이어트의 5개로 축소했다. 백엔드 136개, 프런트 12개와 TypeScript·빌드가 통과했다. 각 분야의 직접 후보 유지, 삭제한 관심 값의 추천·대화 API 거절(422)을 확인했다. 로컬 브라우저에서 5개 선택지·복수 선택 후 다음 단계 이동·식습관의 모름 유지도 확인했다. 원본 상품 DB는 변경하지 않았다. 아래 실제 GPT 호출·7개 관심 분야 화면 기록은 축소 전 검증 이력이며 이번 변경에서 외부 AI를 다시 호출하지 않았다.

2026-10-23, canary에서 정책2026-10-23.2를 검증했다. 아래는 가상 성인 조건과 공개 상품을 사용한 구현 검사이며 실제 사용자 피드백·독립적인 영양학/임상 검수는 별도다.

## 구현 범위

- 관심 분야 일곱 개, 목적 중심/관련 성분/보류 구분, 원료별 기능 문장 대조.
- 미충족 분야와 세부 목적을 우선한 후보 선정, 가격은 이후 동점 처리. 포장 변형 중복 정리.
- 현재 DB의 눈 특화 후보 부족 안내, 관련 영양소 탐색 정보 분리, 모름 상태의 안내 흐름.
- 검토한 혈당3개·체지방1개 범위, 질환 진단·의약품·임신·수유·알레르기 및 추가 범위 확인.
- 같은 혈당·체지방 기능 제품 추가 제한, 카페인 추가 확인·수면 기능·기존200% 제한 등 보류 유지.
- 분류 자료30개 상품·45개 성분별 표시 연결. 원본 DB·표시 검수 상태·관찰일은 보존.

## 자동 검사

백엔드133개, 프런트12개 검사와 TypeScript·배포 빌드가 통과했다. 원본 상품 DB 무결성 검사14,587건과 공식 썸네일88개/공개 상품87개 검사도 통과했다.

`backend/tests/test_recommendation_v2.py`는 설계 기대 사례를 행동 검사로 옮겼다. B 중심 우선·포장 변형·눈 분야 부족·모름·복수 목적·특화 확인·질환 진단·기존 같은 기능·구미/츄어블·예산/제형·고함량 제한·표시 변경·성분 오인·실제 근거 ID·정보 최소화·입력 순서 독립성을 포함한다. 표시 기준·부등호·단위 미확인도 후보에서 제외한다.

```sh
.venv/bin/python -m pytest -q
python3 scripts/validate_product_database.py
python3 scripts/validate_product_thumbnails.py
cd frontend
npm test
npm run build
```

## 브라우저

프런트5174에서 가상 프로필로 동의·설문·실제 추천을 실행했다.

- 관심 분야 일곱 개와 설명 표시, 기존 ‘다양한 성분 보기’ 제거.
- 모름 선택 시 임의 제품 추천 없이 안내와 일반 AI 대화로 이동.
- 혈당 선택 시 새 주의조건과 범위 확인 표시. 해당 없음만 선택하고 확인을 빠뜨리면4단계에 머물며 오류 안내, 확인 후5단계 이동.
- 일반 활력 조건에는 특화 확인을 강제하지 않음. 5,000원 이하·제형 무관에서 B 중심 세 후보와 실제 GPT 설명·출처 표시 확인.
- 눈 건강 조건에서 목적 중심 후보 부족과 별도 관련 성분 정보가 표시되는지 확인.

현재 local5174는 새8001 백엔드를 사용한다. 서버 재시작으로 기존 임시 세션이 끝날 수 있으므로 이전 화면에서는 새로고침하고 동의·설문을 다시 시작한다. 기존8000·4173 프로세스와 production/Render 운영 환경은 변경하지 않았다.

## 한계

임베딩 모델이나 벡터 DB를 도입한 작업은 아니다. 목적 분류가 없는 상품을 임의로 채택하지 않으며 눈 특화 상품은 추가 수집·검수가 필요하다. 단일 호출의 응답 시간이 모든 질문의 성능을 보장하지 않는다. 성분·원문 연결과 형식 검사가 GPT 설명의 모든 의미 오류를 검출하는 것은 아니다.

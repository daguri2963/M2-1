# 프런트엔드 검증 기록

2026-10-20 (Asia/Seoul). React·TypeScript·Vite의 로컬 프런트엔드만 검증했다. 실제 추천·Gemini·서버 연동에 대한 통과 결과가 아니다.

## 자동 검사

`frontend/`에서 `npm test`: **8개 통과**.

1. 필수 1~4단계의 미입력 차단, 선택 5단계 건너뛰기.
2. 기존 제품 선택 시 실제 선택 필요, 모름·목록에 없음은 임의 제품을 만들지 않음.
3. 모름·해당 없음과 다른 선택의 배타 처리.
4. 비교 최대2개, 해제, 세 번째 선택의 명시적 교체.
5. 해시 경로와 명시적 오류 상태 파싱.
6. 단위가 같아도 함량 기준이 다르면 직접 비교 불가.
7. 공개 정적 데이터 87개·보류 SKU 제외·OCR/내부 후보 미포함·칼슘 4정 기준 보존.
8. 식품유형에 기능성 성분 접미어가 있어도 일반식품으로 잘못 분류하지 않음.

`npm run build`: TypeScript 검사 및 Vite 정적 빌드 **통과**. `frontend/dist/` 생성. 제품 데이터와 React 코드를 분리해 단일 대형 청크 경고를 해소했다.

## 실제 브라우저 확인

Codex 인앱 브라우저로 실제 로컬 페이지를 조작했다. 개발 화면 확인 후 최종 `dist`를 Vite preview로 실행해 정상 흐름을 다시 확인했다.

| 확인 흐름 | 결과 |
|---|---|
| 동의 미선택 상태에서 시작 | 두 필수 안내 확인 오류, 진행 차단 |
| 관심 분야 미선택으로 다음 | 인라인 오류 표시 |
| 관심 분야 선택 → 다음 → 이전 | 선택 `aria-pressed=true` 유지 |
| 기존 제품 상태 선택하되 실제 제품 미선택 | 필수값 오류 |
| 기존 제품 검색의 없는 제품 | 검색 없음 안내, 목록에 없음으로 진행 가능 |
| 5단계 선택 항목 건너뛰기 | 고정 예시 3개와 입력 요약으로 연결 |
| 세 번째 비교 제품 선택 | 교체 모달, 두 제품만 유지 |
| 교체 모달 Escape | 취소 후 모달 닫힘 |
| 제품 교체 → 비교 | 새 제품으로 슬롯 변경, 상세 연결 |
| 차이만 보기 | 동일 항목이 실제로 제거됨. 두 표본에서 12→9행, 30→26행 확인 |
| 가격/검수 날짜 | 전체 비교에서 ‘가격 확인일’, ‘표시정보 검수일’ 별도 행 확인 |
| 상세 → 이 제품 질문하기 | 현재 제품 맥락과 검수 표시 근거 연결 |
| 대화 질문·진행 | 미리 작성된 체험 답변과 제품 출처 링크 표시 |
| `#/chat?preview=1` 실패 설정 → 질문 | 오류 안내, 같은 질문 재시도 성공 |
| 대화 초기화 | 웰컴과 질문 칩 복구 |
| 새로고침 | 대화·설문·비교 상태 초기화, 빈 상태 안내 |
| 결과 직접 접근(답변 없음) | 설문 시작/예시 보기 복구 경로 |
| 설문4 직접 접근(동의 없음) | 동의 화면부터 시작 |
| 결과 없음·정보 부족·제한·호출 실패 URL | 각 상태 표시, 오류 재시도 후 예시 복구 |
| 보류 SKU 직접 URL | 제품 찾을 수 없음, 목록 복귀 |
| 제품 검색 결과 없음·초기화·유형 필터 | 실제 목록 갱신. 유형 접미어 분류 수정 후 반영 |
| 기본 결과·대화의 검증 메뉴 | 기본 화면에서 0개. 별도 preview 플래그에서만 노출 |
| 설문·대화의 고정 비교 바 | 0개. 메뉴 배지와 기존 비교 선택은 유지 |
| 최종 정적 빌드 6화면 흐름 | 실제 동작, 최종 확인 구간 실행 오류 0개 |

개발 중 Vite 설정 갱신 시 일시적인 HMR/React 캐시 오류가 있었으나 전체 새로고침으로 해소했다. 최종 빌드의 별도 preview 세션에서 위 정상 흐름을 다시 실행했고 새 오류는 발생하지 않았다.

## 반응형 및 접근성 확인

- 홈: CSS viewport 360×800, 430×932, 1280×800, 1440×900에서 문서 가로 넘침 없음.
- 모바일 주요 화면: 360px의 설문·결과·비교·대화·상세에서 가로 넘침 없음.
- 모바일 대화: 390×844 기준 입력 영역 하단 약 761px, 하단 메뉴 시작 778px로 입력창 가림 없음. 환영 상태의 내부 대화 스크롤은 위에서 시작한다.
- 교체 모달의 Escape 취소, 명시적 레이블, 필수 오류 알림, 선택 상태, 본문 바로가기와 포커스 스타일을 구현했다. 대화의 일반/오류 알림과 한글 조합 중 Enter 전송 방지 처리도 포함한다.
- 실제 iPhone/Android 기기·가상 키보드·스크린리더의 전체 수동 검증은 수행하지 않았다. 브라우저의 지정 viewport와 데스크톱 입력으로 확인한 범위다.

## 재현 주소와 범위

개발 서버: `http://127.0.0.1:5173/` (`npm run dev -- --port 5173`).

최종 정적 빌드 미리보기: `http://127.0.0.1:4173/` (`npm run preview -- --port 4173`).

결과 검증 메뉴: `#/results?state=example&preview=1`.
대화 검증 메뉴: `#/chat?preview=1`.
기본 사용 화면에는 개발 상태 선택기를 노출하지 않는다. 실제 오류 메시지·재시도 UI는 유지한다.

후속 서버 구현 시 개인화 추천 근거·제한 정책·성분 중복·API 실패/취소·민감정보 전송 및 보관·동의·보안 검증이 별도로 필요하다. 이번 검증으로 그 기능이 완성됐다고 보지 않는다.

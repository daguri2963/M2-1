# 백엔드 API와 데이터 흐름

FastAPI + SQLite + Google GenAI SDK. 프런트는 기존 React·TypeScript·Vite를 유지한다. 상품을 정적 JSON에서 읽던 실행 경로를 HTTP 어댑터로 교체했다. JSON 파일은 오프라인 재현·형식 검사에 남으며 실제 제품 목록은 SQLite를 조회한다.

## 요청 경로

| 요청 | 용도 | 동의 필요 |
|---|---|---|
| `GET /api/health` | 서버 준비·AI 설정 유무·동의/정책 버전 | 아니오 |
| `GET /api/products` | 검수 완료 87개 조회 | 아니오 |
| `GET /api/products/{id}` | 품번별 상세 조회, 보류·없는 품번 404 | 아니오 |
| `POST /api/compare` | `productIds` 두 개의 표시 비교 | 아니오 |
| `POST /api/sessions` | 성인·처리·AI 전송 동의 후 임시 연결 생성 | 동의 본문 |
| `DELETE /api/sessions/current` | 연결 폐기 | 예 |
| `POST /api/recommendations` | 설문에 따른 정책 후보·근거·AI 설명 | 예 |
| `POST /api/overlap` | 등록 제품의 표시 성분 중복 | 예 |
| `POST /api/chat` | Gemini Agent·RAG 대화 | 예 |

개인 입력 요청은 메모리에만 있는 `X-Session-Token`을 사용한다. 임시 연결은 기본 30분이며 서버 재시작 시 사라진다. 동의는 별도 버전으로 확인한다. 이는 로그인이나 영구 사용자 기록이 아니다. 워커 1개로 운영하며, 여러 인스턴스로 확장하려면 연결·요청 제한 저장소를 공유하도록 변경해야 한다.

## 설문 계약

```json
{
  "interests": ["뼈·근육 건강"],
  "habits": ["다양하게 먹는 편이에요"],
  "existing": "없어요",
  "productIds": [],
  "cautions": ["해당 없어요"],
  "budget": "3,000원 이하",
  "form": "정제·캡슐"
}
```

추천 응답은 `status`, `message`, `nextStep`, `policyVersion`, `products`, `reasons`, `evidence`, `overlap`, `notices`, `ai`를 담는다. 상태는 `ok`, `empty`, `insufficient`, `restricted`다. 조건 부족·추천 제한은 기대하는 정상 결과이며 네트워크 실패로 위장하지 않는다. `nextStep`은 다시 확인할 설문 단계다.

`ai.mode=gemini`일 때 생성 설명·검증된 인용·모델명을 제공한다. AI 오류여도 정책 후보는 유지하고 `ai.mode=unavailable`에 사유를 담는다. 채팅 실패는 오류 상태코드로 반환하고 예시 답변을 표시하지 않는다.

오류 형식은 `{"error":{"code":"...","message":"..."}}`다. 입력 오류 422, 동의 없음/만료 401, 제품 없음 404, 요청 제한 429, AI 설정·연결 오류 503, AI 전체 기한 초과 504다. 원래 입력값이나 공급자 오류 원문·비밀정보는 오류 응답에 넣지 않는다.

## Agent와 RAG

모델: 실제 계정에서 접속을 확인한 `gemini-3.5-flash-lite`(환경변수로 설정). `gemini-3.8-flash`에서도 실제 도구 실행과 인용 검증을 확인했으나, 공개 상품 설명의 응답 지연을 줄이기 위해 경량 모델을 선택했다. 단일 샘플 속도는 부하 시 보장값이 아니다.

첫 호출은 모델이 제공된 여러 함수 중 도구를 선택하게 한다. 필요한 근거가 부족하면 도구 선택·실행을 한 번 더 진행한다. 도구 선택 단계 최대 2회, 단계당 호출 최대 4개, 최종 구조화 설명 1회다. 명시한 제품·추천에 대한 근거가 확보되면 불필요한 추가 선택 단계를 생략한다. 모델 응답 파트는 서명까지 보존한다.

상품 검색은 정보 탐색과 개인 추천을 구분한다. SQL문은 모델이 작성하지 않으며 등록된 함수와 검증한 인자로만 조회한다. 외부 상품 표시·대화 이력은 명령으로 취급하지 않는다. 최종 JSON은 공급자가 지원하는 스키마와 별도로 서버에서 엄격히 검사한다. 조작된 출처·후보 밖 추천·검수되지 않은 숫자나 용량 지시는 거부한다.

외부 API 재시도 폭증을 피하도록 SDK 자동 재시도를 제한한다. AI 실행은 동시 2건, 전체 45초 기한, 세션당 추천·대화 합계 분당 10요청으로 제한한다. 이는 초기 로컬 구현의 제한이며 공개 운영에서 부하·비용·접속 환경에 맞춰 조정한다.

## 정보 처리

- 키는 루트 `.env` 또는 서버 환경변수에서만 읽는다. 프런트 키·localStorage·비밀키 포함 URL을 사용하지 않는다.
- 설문·대화 원문은 서비스 서버의 파일·DB·접속 로그에 영구 저장하지 않는다. 임시 연결에는 만료 시각만 저장한다.
- Gemini에는 관심·예산·제형, 일반 질문·필터링한 최근 대화 일부, 공개 상품·근거를 전달한다. 주의조건·식습관·기존 복용 내역은 서버에서 검사하며 원문·내역을 Gemini 문맥에 넣지 않는다. 중복 확인 도구도 상태 요약만 모델에 반환한다.
- [Google 이용조건](https://ai.google.dev/gemini-api/terms)에 따라 무료 서비스의 입력·출력은 개선과 사람의 검토에 사용될 수 있음을 동의 화면에 설명한다. 실제 개인정보나 민감 건강정보를 입력하지 않도록 안내하고 대표 형식·의료 질문을 로컬에서 제한한다.
- 서비스 서버의 삭제·미저장은 Google의 보관까지 삭제한다는 뜻이 아니다. 제공자 처리 범위를 별도로 안내한다.
- 개인 응답은 `Cache-Control: no-store`로 반환하고 CORS 허용 출처를 설정한다.

## 최초 접속 지연

프런트엔드는 독립적으로 열리고 건강상태 확인을 시작한다. 한 번의 확인 요청은 5초 기한이며, 서버가 준비되지 않으면 안내를 띄우고 전체 75초 이내에서 다시 확인한다. 준비되면 자동 진행하고, 기한을 넘기면 재시도 버튼을 제공한다. Gemini 생성 로딩과 서버 기동 안내를 구분한다. 창을 오래 열어둔 경우에도 준비 상태를 주기적으로 다시 확인한다.

[Render 무료 서버](https://render.com/docs/free)는 유휴 후 기동 지연과 파일 변경 유실이 있으므로, 상품 DB는 읽기 전용 배포 파일로 포함한다. 향후 피드백을 서버에 저장한다면 별도 영구 저장소가 필요하다. Render 외부 배포 구성과 실제 확인 결과는 [배포 기록](deployment.md)을 참고한다.

## 실행과 배포 준비

로컬 백엔드: `.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --no-access-log`.

기존 미리보기 프로세스를 유지하기 위해 로컬 화면은 기본적으로 `http://127.0.0.1:8000` 또는 `http://localhost:8000`에 직접 연결한다. 원격 정적 배포에서는 `VITE_API_BASE_URL`에 공개 백엔드 URL을 지정하고 백엔드 `ALLOWED_ORIGINS`에 프런트 URL을 넣는다. 이 URL은 공개 설정이며 Gemini 키와 다르다. 같은 출처 배포는 빈 API 기본 URL을 사용할 수 있다.

Dockerfile은 백엔드와 검수 SQLite만 담고 실제 `.env`·원본 이미지·프런트 의존성을 복사하지 않는다. 프런트는 별도 정적 빌드와 87개 썸네일을 배포한다. 사용자의 배포 지시와 저장소 접근·비밀키 전송 승인 후 Render 무료 백엔드와 정적 사이트를 생성했다. 키는 서버 환경변수에만 등록했다.

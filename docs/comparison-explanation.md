# 두 제품 AI 비교 해설

canary 로컬 구현. 운영 사이트 반영 전이며 기존 두 제품 표시정보 비교(M07)에 덧붙이는 선택 기능이다. Must는 기존 8개를 유지한다.

## 사용자 흐름

제품 두 개 선택 → AI 요약·핵심 차이 최대 세 개·선택 기준 → 기존 표시정보 비교표 순서다. 정확한 수치와 원문은 각 카드의 ‘확인된 표시 보기’에서 펼친다. 설명의 공식 출처도 접어서 제공한다.

비교표는 동의 없이 바로 조회한다. AI 해설은 기존 이용 안내·동의 이후 자동 생성한다. 동의 안내는 비교 화면 안에서 펼쳐지므로 제품 선택이 유지된다. 설문·대화·개인 조건은 비교 해설 요청에 포함하지 않는다.

요청 전 350ms 동안 제품 선택 변경을 기다린다. 교체·제거·동의 철회 시 이전 해설을 숨기고 예약/진행 요청을 취소한다. 취소된 응답·오류는 새 선택을 덮어쓰지 않는다. 응답의 제품 ID와 순서가 다르면 표시하지 않는다. 동의 세션이 끝나면 비교 화면과 선택을 유지한 채 재동의한다.

## 서버와 AI의 역할

- `backend/comparison.py::comparison_facts`: 검수 SQLite의 선택한 두 제품만 읽는다. 식품유형·기능·주요 표시 성분·제형·섭취방법·규격·관찰 가격·주의·알레르기 및 공통 성분 우선 최대 여덟 개의 정량 사실을 만든다.
- 함량 대소는 정확한 하루 정량, 같은 기준 문구(공백 제외), 같은 단위가 확인된 경우에만 분류한다. 단위·섭취량 환산, 가격당 효능, 하루 비용은 계산하지 않는다. 미표시를 미함유나 0으로 바꾸지 않는다.
- 사실별 공식 상품 페이지 또는 검수 표시 출처 ID를 연결한다. 가격에는 확인일과 관찰 단품 가격이라는 설명을 유지한다.
- 같은 성분·기능 표시가 전체 원재료·배합 동일성이나 약학적 대체성을 뜻하지 않는다. 미지원 개인 적합성·치료·섭취량 변경·병용 안전 판정을 제공하지 않는다.
- AI는 서버가 만든 사실을 읽고 중요한 차이를 선택해 한국어로 설명한다. 비교 전용 생성 경로는 도구 선택 루프를 새로 실행하지 않으며, 현재 코디세이 GPT 전송 클라이언트와 동시 실행 제한을 재사용한다. 기존 AI Agent 대화·추천 경로는 별도로 유지한다.

AI는 요약/핵심 차이/선택 기준의 JSON을 반환한다. Pydantic 구조·길이, 허용된 사실 ID, 두 제품의 출처 포함 여부, 숫자·URL·개인 복용 판단 등 금지 표현을 서버에서 검사한다. 수치가 필요한 경우 AI 본문 대신 서버의 정확한 표시값을 펼쳐서 보여준다. 제공자 강제 JSON 출력 기능을 사용한다고 주장하지 않는다. 서버 검사가 문장의 모든 의미 오류를 검출하는 것은 아니므로 실제 출처와 오류 가능성을 함께 안내한다.

## API

`POST /api/compare`는 기존 공개 비교표 API로 유지한다.

`POST /api/compare/explanation`은 유효한 `X-Session-Token`을 요구한다. 요청은 `{"productIds":["600000129","600000128"]}`처럼 서로 다른 공개 검수 품번 두 개만 받으며 추가 필드를 거절한다.

응답은 `mode=ai`, `productIds`, A/B와 제품명을 연결하는 `products`, `summary`, `highlights`, `selectionGuide`, `citations`, `notice`, `version`, `cached`를 제공한다. 문단의 `factIds` 및 카드의 `factId`는 서버 사실을 참조하고 카드에는 해당 `fact`의 원문 표시값도 포함한다.

401은 동의 재확인, 422는 입력 오류, 404는 보류/없는 제품이다. 생성 한도/혼잡은429, 생성 시간 초과는504, 설정/형식/근거/내용 검사 실패는503으로 설명 영역에서 처리한다. API·공급자 예외 원문이나 인증키를 노출하지 않는다. 오류 시 가짜 AI 해설을 표시하지 않고 비교표와 재시도 버튼을 유지한다.

## 재사용·실행 제한

제품 순서(A/B), 조회한 사실·출처·확인일, 모델·접속 주소, 비교 프롬프트 버전을 해시한 키로 프로세스 메모리에 최대128개·1시간 저장한다. 공개 상품 해설만 재사용하고 사용자 세션·설문·대화는 저장하지 않는다. 실패 결과는 저장하지 않는다. 역순은 별도 해설이며 자료·모델·버전 변경은 캐시를 무효화한다. 서버 재시작 시 캐시는 사라진다.

동일 조합의 진행 요청은 공유한다. 한 브라우저가 취소해도 다른 대기자의 요청은 취소하지 않으며 완료 결과를 재사용할 수 있다. 전체 고유 진행 요청은 최대8개, 실제 AI 동시 실행은 기존 추천·대화와 합쳐 최대2개다. 기존 세션별 요청 제한을 적용한다. 서버 종료 시 진행 작업을 취소하고 공급자 클라이언트를 닫는다.

## 검증

- 백엔드: 동의·입력·출처·정량 기준·미확인값·금지 표현·공급자 실패·시간 초과·재시도·캐시 만료/자료/모델 변경·동시 요청 공유·연결 취소를 검사한다.
- 프런트: 선택 중간 요청 취소, 늦은 응답·오류 무시, 제품 순서 불일치 거절, 재시도를 검사한다. TypeScript와 배포 빌드를 확인한다.
- 실제 GPT: [공개 제품 세 쌍의 로컬 호출 결과](comparison-live-check.json). `scripts/check_comparison.py --run-live`로 실행하며 호출량을 사용한다. 기본 실행은 요청을 전송하지 않는다.
- 실제 브라우저: 동의 전 비교표, 화면 내 동의 후 자동 생성, 원문/출처 접기·펼치기, 제품 교체·제거와 표시정보 비교를 확인한다.

# 관심 분야 분류표와 예상 추천 사례 v2

작성일: 2026-10-23 · 상태: 구현 전 설계 기록

> 이 문서는 당시 분류 초안과 기대 사례를 보존한다. 이후 canary 구현의 현재 규칙·개방 범위는 [추천 정책 v2](recommendation-policy-v2.md), 실행 결과는 [로컬 검증 기록](recommendation-v2-live-check.json)을 따른다. 아래 ‘미변경·보류·미실행’ 표기는 설계 작성 당시 상태다.

사용자가 정한 새 관심 분야와 현재 검수 DB를 연결한 작업 문서다. 이번 단계는 분류와 기대 동작을 정의한다. **화면 선택지·추천 함수·DB·기존 제외 규칙은 아직 변경하지 않았다.** 아래 예상 결과는 새 정책의 목표이며 현재 구현의 실행 결과나 특정 사용자의 섭취 권고가 아니다.

## 1. 관심 분야 구성

화면 순서는 다음과 같다. 기존 ‘다양한 성분 보기’를 제거하고 ‘혈당 관리’와 ‘다이어트’를 추가한다. ‘잘 모르겠어요’는 유지한다.

| ID | 화면 이름 | 사용자에게 설명할 내용 |
|---|---|---|
| vitality | 일상의 활력 | 에너지 대사에 관련된 성분과 제품 표시를 알아봐요. |
| bone_muscle | 뼈·근육 건강 | 뼈 건강과 정상적인 근육 기능에 관련된 제품을 살펴봐요. |
| gut | 장 건강 | 유산균·프리바이오틱스 등의 표시된 기능을 비교해요. |
| eye | 눈 건강 | 눈 건강을 목적으로 한 제품의 기능 차이를 알아봐요. |
| glucose | 혈당 관리 | 식후 혈당 관련 기능이 표시된 제품 정보를 살펴봐요. |
| weight | 다이어트 | 체지방 감소 기능이 표시된 제품 정보를 살펴봐요. |
| unsure | 잘 모르겠어요 | 관심 분야의 차이를 먼저 알아보고 선택해요. |

구체적인 여섯 분야는 복수 선택할 수 있다. ‘잘 모르겠어요’는 다른 분야와 함께 선택하지 않는다. 기존 성인 대상·동의 절차는 유지한다. 관심 분야 선택은 질환 진단이나 영양 결핍 판정을 뜻하지 않는다.

## 2. 분류 원칙

분류에는 검수된 기능정보, 해당 기능을 내는 성분, 제품 구성, 표시된 주의사항을 함께 사용한다. 이름이나 ‘에너지’, ‘시각’ 같은 단어 하나만으로 자동 분류하지 않는다.

- **목적 중심 후보(D):** 선택 목적이 해당 제품의 주요 구성과 검수 기능정보에 직접 연결된다. 모든 성분이 그 분야에만 해당해야 한다는 뜻은 아니다.
- **관련 성분 포함(R):** 관련 영양소나 기능은 있으나 선택 목적에 특화된 제품으로 보기는 어렵다. 목적 중심 후보와 같은 등급으로 섞지 않고 필요할 때 별도 대안으로 설명한다.
- **추천 보류(H):** 관련 기능이 있어도 범위·표시·주의조건·정량 검토가 완료되지 않아 자동 추천을 허용하지 않는다.
- **해당 없음(X):** 그 관심 분야와 연결할 제품 표시 근거가 없다.

D/R은 기능의 강도·효능·안전성 순위나 의학적 적합도 점수가 아니다. 분류와 추천 가능 여부를 별도 필드로 관리한다. 분류가 D여도 보류 조건이 있으면 추천되지 않는다.

## 5. 후보 선별과 순위의 목표 동작

처리 순서: **필수 근거·개인 주의조건 확인 → 분야별 분류 → 예산·제형·기존 제품 확인 → 목적 중심 후보 우선 → 포장 변형 정리 → 근거 설명**.

1. 미검수·일반식품·정량 미확인·지원 범위 밖·기존 제품 중복 등 현재의 확인 절차를 우선한다. 혈당·체지방의 새 조건은 별도 검토를 거쳐 추가한다.
2. 목적 중심 후보가 있으면 관련 성분 제품이 저렴하다는 이유로 위로 올라오지 않는다. 가격은 관련성 평가 뒤의 선택 기준이다.
3. 관련 성분 대안은 목적 중심 후보와 같은 목록에서 순위를 경쟁시키지 않는다. 기본 후보를 세 개로 채우기 위해 임의로 승격하지 않는다.
4. 뼈·근육은 같은 카드 안에서도 ‘뼈 중심’과 ‘근육 기능 중심’을 구분한다. 사용자 의도를 한 가지 성분으로 단정하지 않는다.
5. 복수 관심은 하나의 복합 제품이 모든 목적을 해결한다고 단정하지 않는다. 분야별 후보 또는 검수된 복합 후보를 구분하고, 충족하지 못한 분야도 표시한다.
6. 포장 변형은 브랜드·이름만으로 합치지 않는다. 검수된 기능성 구성·하루 기준 정량·제형·섭취방법 등을 대조해 후보군 중복을 정리한다. 제품이 완전히 동일하거나 약학적으로 대체 가능하다고 표시하지 않는다.
7. 후보는 최대 세 개이며 한 개나 두 개만 나와도 정상이다. 직접 후보가 없으면 그 이유와 탐색 경로를 제공한다.
8. 200% 초과 일괄 제외는 별도 재검토 항목이다. 이번 분류 작업만으로 제거하지 않으며, 이를 의학적 상한이나 안전 판정으로 설명하지 않는다.
9. 식습관 응답만으로 결핍을 추정하지 않고 증상 개선·감량량·혈당 수치 변화나 개인별 복용량을 생성하지 않는다.

## 6. 혈당 관리·다이어트 개방 전 조건

두 분야는 이번 분류표에 포함하되, 기존 제외 정규식에서 단어만 지워 곧바로 추천을 허용하지 않는다. 아래는 구현 전에 반영·검증할 설계 조건이다.

- 현재 ‘의약품 복용·치료 중’ 질문이 진단은 받았지만 약을 먹지 않는 경우를 놓치지 않도록, 질환 진단·치료·의료진 관리 여부까지 범위를 분명히 한다. 병명·검사값·약품명 등 자유 입력은 수집하지 않는 방향이다.
- 해당 주의조건이 있으면 개인 제품 추천을 제한하고 공식 표시 탐색으로 안내한다. 모르는 상태는 조건 부족으로 처리한다. 임신·수유·알레르기 확인 필요에 대한 기존 제한도 유지한다.
- 바나바 기능 표시를 당뇨 치료·약 대체·누구에게나 적합하다는 안내로 확장하지 않는다.
- 녹차추출물 제품은 실제 검수한 카페인·간질환·의약품 관련 주의사항을 후보 판정과 화면에 연결한다. 카페인 주의 여부를 확인하는 항목이 필요하면 서버에서만 처리하는 제한된 선택형 입력으로 설계하고 동의 문구를 맞춘다. 관련 정보가 없거나 불명확한 상태를 ‘주의 없음’으로 처리하지 않는다.
- 기존에 체지방 기능 제품을 등록했다면 성분명이 달라도 같은 목적 제품의 추가 추천을 막는 프로젝트 범위 규칙을 검토한다. 동일 성분 중복 검사만으로 충분하다고 판단하지 않는다. 혈당 기능 제품의 중복도 같은 원칙으로 검토한다.
- 혈당 관리나 다이어트 선택이 없는 사용자의 활력·장 건강 후보에 해당 특화 복합 제품을 끼워 넣지 않는다.
- 일부 원료가 추가되어도 수면·성별·간 건강 등 다른 미지원 범주를 자동 개방하지 않는다.

이는 개인의 안전을 보증하는 의료 규칙이 아니라 서비스가 자동 추천을 제한하는 설계다. 실제 상품 주의사항 검토와 구현 검사가 완료되기 전에는 해당 상품을 H에서 해제하지 않는다. 건강기능식품과 질환 치료의 범위 구분은 [질병관리청 안내](https://health.kdca.go.kr/healthinfo/biz/health/gnrlzHealthInfo/gnrlzHealthInfo/gnrlzHealthInfoView.do?cntnts_sn=6548)를 참고한다.

## 8. 후속 구현 범위

1. 상품별 목적·성분·기능·근거 ID·분류·보류 이유를 구조화한다. 원본 DB의 검수 상태는 분류 판단으로 덮어쓰지 않는다.
2. 현재의 관심 키워드 매칭·가격 우선 동점 처리를 이 분류와 기대 사례로 교체한다. 가중치 숫자와 최종 동점 규칙은 아직 확정하지 않았다.
3. 프런트 선택지와 백엔드 허용값을 함께 갱신한다. 구체 분야 여섯 개의 복수 선택과 ‘모름’ 단독 선택을 지원한다. 기존 제형 그룹에 없는 구미·츄어블 처리도 명시한다.
4. 새 주의조건이 필요한 범주에만 최소 입력·확인 절차를 추가하고 서버에 한정해 처리한다. GPT에는 진단·복용·주의조건을 전송하지 않는다.
5. 추천 근거 검색은 매칭한 성분·기능 필드와 주의사항을 우선 조회하도록 바꾸고, GPT가 선정 후보나 근거 범위를 임의로 확장하지 못하게 한다.
6. 위 사례를 검사로 옮겨 canary에서 로컬 검증한 뒤 dev PR로 통합한다. 현재 운영 배포는 이 문서 작성으로 변경되지 않는다.

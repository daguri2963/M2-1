## 이용 안내와 정보 흐름

AI가 생성한 설명이며 오류가 있을 수 있다는 점과 일반 성인의 제품 탐색 범위를 화면에 표시한다. 추천·대화·AI 비교 해설 전 성인 이용·정보 처리·코디세이/모델 제공자 전송 안내에 동의하도록 한다. 공개 제품 목록·상세·표시 비교는 동의 없이 가능하다.

설문은 선택형 관심·식습관·기존 등록 제품·주의조건·선택 예산/제형을 받는다. 이름·연락처·질환명·약품명·검사 수치는 요구하지 않는다. 기존 제품/주의조건은 서버 정책 확인에 사용하지만 외부 모델에 설문 전체를 전달하지 않는다. 외부 선호는 관심·예산·제형으로 줄인다. 비교 AI에는 공개 품번2개와 표시 사실만 전달한다.

대화는 민감/개인 판단/긴급 의도를 서버에서 먼저 분기하고, 민감한 이력과 뒤따른 답변을 모델 이력에서 제외한다. 정규식 기반이므로 모든 민감 표현을 검출하는 개인정보 탐지기라고 보장하지 않는다. 실제 건강정보를 입력하지 않도록 안내한다.

## 저장·삭제와 외부 처리

- 브라우저 입력·대화·임시 토큰은 메모리에서 사용하며 새로고침/초기화/철회 시 지운다. 회원 계정·장기 대화 저장은 없다.
- 서버는 세션 토큰/만료 시각과 요청 제한 정보를 메모리에 보관한다. 건강 입력·대화 원문을 사용자 DB에 영구 저장하지 않는다. 재시작 시 세션·캐시는 사라진다.
- 세션은 생성 시 기본30분 고정 만료다. 매 요청으로 연장되는 방식이 아니다. 철회 시 보호 API를 다시 사용할 수 없다.
- 공개 제품쌍 AI 비교 캐시는 최대128개·1시간이다. 개인 설문/대화 캐시가 아니다.
- COPA 요청에 `store=False`를 사용한다. 이는 **COPA/모델 제공자와 호스팅 사업자의 모든 로그가 남지 않는다는 보증이 아니다.** 외부 처리 범위는 서비스 내부 메모리 삭제와 구분한다.
- 서버 응답은 `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`를 설정하고 실행 시 접근 로그를 끈다. 원문 요청/키/예외 상세를 보고서에 기록하지 않는다.

## 비밀키와 설정

로컬 키는 저장소 루트 `.env`의 `COPA_API_KEY`에 두고 Git에서 제외한다. `.env.example`만 예시로 추적한다. 프런트의 `VITE_` 변수·소스·화면·검사 결과에 키를 넣지 않는다. Render 운영 백엔드 환경변수에도 사용자 승인 후 등록했다.

| 설정 | 운영 값/의미 |
|---|---|
| `COPA_API_KEY` | Render 백엔드 비밀값. 문서에 값 기재하지 않음 |
| `COPA_BASE_URL` | `https://copa.codyssey.kr/v1` |
| `COPA_MODEL` | `gpt-5.4` |
| `ALLOWED_ORIGINS` | 현재 프런트 주소와 유지 중인 이전 주소 |
| `SESSION_TTL_SECONDS` | 기본1800 |
| `AI_TIMEOUT_SECONDS` | 기본45 |
| `VITE_API_BASE_URL` | 프런트의 공개 API 주소 `https://m2-1-api.onrender.com` |

[copa.py](../../backend/copa.py)는 키 전송 대상 HTTPS 호스트/경로를 제한하고 리디렉션을 막는다. Gemini 키가 남아 있어도 현재 코드의 대체 제공자로 사용하지 않는다. 키 유출이 발견되면 즉시 폐기·재발급하고 운영 환경변수를 바꾸어 재배포한다. `.gitignore`는 과거 커밋에 이미 들어간 비밀을 삭제하는 도구가 아니므로 이력도 확인해야 한다.

## 서버·실패 처리

내부 기본 제한은 동의 세션 최대1000개, 세션별1분10회(추천·대화·AI 비교 해설), 공유 AI 동시 실행2개다. 슬롯 대기는1초, Agent 실행 및 비교 생성 제한은45초다. 비교의 서로 다른 대기 키는 최대8개다. 중복 검사 API에는 현재 동일한 분당 제한이 적용되지 않는다. 이 값은 단일 프로세스 보호 장치이며 공급자 한도나 동시 사용자 보장이 아니다.

화면의 서버 준비 확인은 기본75초 범위에서2초 간격으로 재시도한다. 네트워크·실행 상황에 따라 정확한 UI 경과 시간은 달라진다. 서버 대기 안내와 AI 생성 상태를 구분한다.

| 상황 | 사용자에게 보이는 동작 | 운영 확인 |
|---|---|---|
| 백엔드 대기/연결 실패 | 준비 안내·자동 확인·실패 후 재시도 | Render 상태·health·배포 로그 |
| 동의 만료/철회 | 재동의 안내·개인 요청401 | 현재 동의 버전·서버 재시작 여부 |
| 사용량/요청 초과 | 한도/요청 많음 안내·재시도 | COPA 사용량과 내부429 구분 |
| 근거 부족/개인 판단 | 질문 구체화·표시/전문가 확인 안내 | 질의 유형·공식 자료 범위 |
| GPT 오류·검증 실패 | 대화/해설 실패 안내. 추천 후보와 공개 비교표는 별도 유지 | 제공자 상태·출처/형식 검증 오류 |
| 백엔드 자체 중지 | 서버 기반 목록·추천·비교도 영향 | AI 키만의 문제로 설명하지 않음 |

현재 Render는 무료 인스턴스로 구성했으며 사용자의 컴퓨터를 켜 둘 필요는 없다. Render 시간·전송량·빌드와 COPA AI 사용량은 서로 다르고 워크스페이스의 다른 서비스와 공유될 수 있다. 최신 남은 한도·요금은 각 대시보드에서 확인하며 이 문서에 고정 수치로 보장하지 않는다. 별도 시험 서버·유료 디스크·맞춤 유료 도메인은 만들지 않았다.

## 배포·갱신·복구

1. canary에서 변경·로컬 검사 → canary CI → dev PR → dev 검사 → 관리자가 production PR/병합한다.
2. Render 두 정적 사이트와 API는 production을 기준으로 한다. 프런트는 `frontend`에서 `npm ci && npm run build`, 공개 폴더는 `dist`다. 백엔드는 루트 Dockerfile을 사용한다.
3. 문서만의 변경은 배포 필터에 따라 앱 재배포를 생략할 수 있다. `backend/**`, DB, **`data/recommendation/**` 등 실행 의존 파일**의 변경을 필터가 포함하는지 확인하고, 누락되면 필터 갱신 또는 해당 production 커밋을 수동 배포한다. 실제 대시보드 필터에 모든 미래 의존 경로가 포함됐다고 가정하지 않는다.
4. health의 제공자/모델/버전, 배포 SHA와 live 상태를 확인한다. 실제 GPT 질문·추천·비교를 가상 조건으로 확인한다. 키 설정만으로 실제 호출 성공을 판정하지 않는다.
5. 장애 시 이전 정상 배포로 복구하거나 되돌림 PR을 같은 승격 경로로 반영한다. DB·분류·동의 화면·서버 버전도 맞춘다. COPA 전환을 되돌릴 때는 단순 키 변경으로 Gemini가 작동하지 않으므로 해당 코드/동의까지 검토한다.

현재 릴리스의 서비스/배포 ID·CI는 [운영 증빙](evidence/production-release-2026-10-23.json)에 있다. 결과 안내를 받을 때까지 접속·키 만료·한도를 관리한다.

## 제출 자료의 개인정보

참여자는 T1 등 가명으로 기록하고 응답 원본의 이름·연락처·계정·개인 건강정보를 가린다. 동의 없이 개인 자료를 공개 저장소에 올리지 않는다. 현재 문서에는 실제 사용자 건강정보·응답 원본을 포함하지 않았다. 구현된 보호 장치는 기록했지만 법률·보안 인증을 받았다는 의미는 아니다.

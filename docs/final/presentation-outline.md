# 서면 심사용 발표 PDF 구성안

2026-10-24 · **현재는 문서 내용 구성안이며 발표 PDF는 다음 단계에서 제작한다.** 시연 영상은 선택하지 않았다. [제출 목차](README.md)

발표 없이 읽어도 문제 → 해결 → AI 기술과 이유 → 구현 → 피드백/개선을 이해하도록 구성한다. 화면·수치마다 검증 범위를 표기하고, 사용자 원본과 개인 기여가 확인되기 전에는 해당 요건 완료를 주장하지 않는다.

| 페이지 제안 | 핵심 내용 | 사용할 근거/시각 자료 |
|---|---|---|
| 1 | 영양제 첫걸음·팀원5명·서비스/GitHub 주소·한 줄 가치 | [기획서](../project-plan.md)·운영 URL |
| 2 | 초보자가 겪는 제품/성분/기준량 선택의 어려움과 대상 | 문제 가설임을 명시, 검증되지 않은 통계 사용 안 함 |
| 3 | 설문 → 후보 → 근거 → 비교/대화 사용자 경험 | [명세서](../functional-requirements.md)의 실제 흐름 |
| 4 | 수집88·공개87·보류1, 원문/OCR/검수/출처 추적 | [아키텍처](architecture.md)·보류 이유 |
| 5 | React/FastAPI/SQLite/COPA 구성과 선택 이유 | 구조 그림·개인정보 경계 |
| 6 | Agent7도구와 RAG 질의 검색, 실제 도구/출처 | [AI 설계](ai-design.md)·M03/M04 실행 로그 |
| 7 | 규칙 후보와 GPT 설명 분리·활력/특화/중복 처리 | 분류/정량의 근거와 한계 |
| 8 | 구현 화면·제품 비교 AI 해설·AI 대화 | [비교 화면](evidence/production-comparison.jpg)·[5분야 화면](evidence/survey-five-goals.jpg) |
| 9 | 구현 검증 결과·오류/제한 처리·배포 |159/15·데이터 검사·실제 API3회 결과. M04 2/3과 한계도 표시 |
| 10 |5개 피드백 개선: 주소·질문 범위·첫 질문·활력·중복 | [개선 표](user-feedback.md). 참여자 원본 확보 여부를 표시 |
| 11 |5명 역할·실제 개인 기여 링크·협업/브랜치 | [기여 문서](team-contributions.md). 미확인 개인 이력은 확인 후 반영 |
| 12 | 현재 한계·향후 보완·접속과 제출 문서 링크 | 외부 장애·자료 갱신·원본/기여 보완 상태 |

PDF 제작 때 한글 글꼴 포함·링크·표 잘림·그림 가독성을 확인하고 페이지별로 렌더링 검수한다. 현재 자료만으로 먼저 제작한다면 사용자5명 증빙과 개인 기여의 미확인 상태도 PDF에 유지해야 한다.

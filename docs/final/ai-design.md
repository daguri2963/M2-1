# AI 활용 설계와 기술적 의사결정

## AI가 맡는 일

AI는 처음 영양제를 고르는 사람에게 성분·표시·제품 차이를 쉬운 말로 설명하는 상담 안내자다. 친절한 약사에게 질문하듯 대화할 수 있게 하되 **실제 약사 자격을 주장하거나 개인 진단·처방을 하지 않는다.** 일반 영양 질문과 제품 질문을 구분하고, 공식 지식/검수 표시가 있는 범위에서 답하며 출처를 함께 보여준다.

후속 로컬 화면 수정에서는 제품 선택 여부에 따라 시작 질문을 구분한다. 미선택은 기존 일반 질문6개, 선택 시에는 해당 제품의 성분 역할·식사/섭취 시간·보관·일반 주의사항4개를 표시한다. 질문은 [제품용 문구 파일](../../frontend/src/data/product-chat-prompts.json)에서 관리하고 기존 `productId` 전달 경로를 사용한다. [후속 로컬 검증](test-results.md)은 운영 API 기준 검증과 구분한다.

후보 선정·필수 제한·정량 계산은 서버 규칙이 담당한다. GPT가 표시 밖 제품·효능·섭취량을 만들어 추천하지 않도록 역할을 나눴다. AI가 실패하면 실패 안내를 내고 예시 답변으로 가장하지 않는다.

## 필수 기술 2개와 코드 위치

| 인정 기술 | 실제 동작 | 핵심 코드·증빙 |
|---|---|---|
| **AI Agent** | LLM이7개 도구 중 호출 대상을 선택, 도구 결과를 받고 다음 실행/답변을 결정 | [agent.py](../../backend/agent.py), [실제 도구 실행 기록](evidence/acceptance-api.json)의 M03·M04 `toolTrace` |
| **RAG** | 질문마다 검수 DB·외부 공식 자료 기반 지식 카드·표시 안내를 검색하고 검색 결과를 모델 입력에 포함 | [repository.py](../../backend/repository.py), [knowledge.py](../../backend/knowledge.py), [label_guide.py](../../backend/label_guide.py), 답변 `citations` |

고정 텍스트를 모든 질문에 붙이는 방식만으로 RAG라고 주장하지 않는다. 모델이 검색 도구에 질의를 넘기고 서버가 관련 자료를 찾아 주는 실행 경로다. 임베딩·벡터 DB·미세조정은 사용하지 않는다. 사진은 표시용이므로 멀티모달 AI가 아니다. 일시적 대화 이력은 Long-term Memory가 아니며 CI를 과제의 자동화 워크플로우 기술로 세지 않는다.

## 모델 연결과 호환성

운영 모델은 코디세이 제공 **`gpt-5.4`**, 주소는 `https://copa.codyssey.kr/v1/chat/completions`다. [copa.py](../../backend/copa.py)가 OpenAI Python SDK의 비동기 Chat Completions를 사용한다. 키는 `COPA_API_KEY`, 모델은 `COPA_MODEL`로 서버에서 읽는다. 허용 HTTPS 호스트/경로를 검사하고 리디렉션을 따르지 않으며 자동 재시도는0이다. 다른 제공자로 자동 전환하지 않는다. Gemini 환경변수가 남아 있어도 현재 코드가 사용하지 않는다.

초기 Gemini 구현 이후 코디세이 제공 키를 활용하고 실제 도구 호출 호환성을 검증해 전환했다. 중계 엔드포인트는 `required`/특정 이름의 tool choice, `response_format`의 JSON schema/object, `reasoning_effort=none`을 지원하지 않는 것을 확인했다. 현재 `tool_choice=auto`, 제한된 도구 인자 스키마와 **서버측 최종 JSON·출처 검증**을 사용한다. 공급자가 최종 출력 형식을 강제한다고 설명하지 않는다. [호환성 결과](../copa-compatibility-check.json)·[로컬 연결](../copa-local-integration.md)·[운영 검증](test-results.md)이 근거다.

## Agent 도구와 루프

| 도구 | 수행 |
|---|---|
| `search_nutrition_knowledge` | 일반 성분 역할·식사·보관 등 공식 지식 검색 |
| `search_products` | 공개 제품명·조건 탐색 |
| `get_product_details` | 선택 품번 표시·출처 조회 |
| `search_evidence` | 제품 라벨·표시 읽기 관련 근거 검색 |
| `check_overlap` | 등록 제품의 같은 성분·확인 가능한 정량 중복 |
| `compare_products` | 두 제품의 서버 표시 비교 |
| `recommend_products` | 설문을 검증한 정책 후보 조회 |

네이티브 도구 루프는 최대2라운드이며 모델 응답당 최대4개 도구 호출을 처리한다. 첫 응답에서 도구가 선택되지 않는 경우를 검증하며, 도구 인자·품번·허용 도구를 검사한다. 마지막 답변 생성 호출은 검색 근거와 허용 제품 ID만 받아 생성한다. 실제 한 요청에서7개를 모두 호출할 필요는 없고 질문에 맞는 도구만 사용한다.

## RAG 자료·검색·출처

| 자료 | 현재 범위 | 검색과 확인 |
|---|---|---|
| 검수 상품 DB | 공개87개 | 이름·질문 키워드/동의어로 조회, 표시 근거와 품번:필드 ID 제공 |
| 일반 영양 지식 |35개 카드·공식 출처12개, 주요 성분10종 | 주제·별칭·질의 매칭, 관련 카드 최대4개. 출처·확인일·원문 발췌 해시 보존 |
| 표시 읽기 안내 | 함량/기준량·영양성분 기준치 등 | 일반 표시 질문을 제품 선택 없이 처리 |

공식 영양 자료 원문은 [nutrition-knowledge.json](../../backend/nutrition-knowledge.json)의 URL·확인일에 연결된다. 현재 자료에는 NIH ODS 등이 포함되며 외국 수치 기준을 한국 제품의 개인 용량으로 옮기지 않는다. 동일 에이전트의 출처 대조 기록이며 독립 임상 검토가 아니다. 제품 자료는 10-19~20, 지식 자료는10-21 확인 기록을 보존한다.

최종 답변은 허용된 인용 ID·공개 제품·후보 범위를 검사한다. 숫자·용량 지시·미허용 제품 등을 제한하며 추천 해설의 인용은 정책 후보로 묶는다. 일반 지식과 제품 표시의 근거를 구분한다. 검색 근거가 없으면 구체화/제품 선택을 안내한다. `함량과 기준량` 시작 질문은 전용 표시 지식 검색으로 해결했다.

## 추천 정책

[policy.py](../../backend/policy.py)·[classification.py](../../backend/classification.py)·[분류 데이터](../../data/recommendation/classification-v2.json)가 규칙을 구현한다. 정책 버전 `2026-10-23.2`, 분류 버전 `2026-10-23.3`이다.

1. 주의조건·기존 제품 미확인·특화 범위 확인을 먼저 처리한다. 제한/정보 부족이면 외부 AI 추천을 요청하지 않는다.
2. 공개 검수 상품 중 정확한 하루 기준 정량·필수 표시·지원 범위를 확인한다. 프로젝트의 기준치200% 초과 제한은 의료적 상한값이 아니다.
3.28개 분류 제품·40개 성분/기능 연결을 원문 표시와 대조한다. 직접 목적 `direct`와 관련 성분 `related`를 구분한다. 관련 제품으로 추천 수를 억지로 채우지 않는다.
4. 기존 제품과 동일 성분, 혈당·체지방 동일 목적 추가 후보를 제한한다. 예산은 관찰한 단품 가격, 제형은 실제 표시 분류를 쓴다. 식습관만으로 결핍을 추정하지 않는다.
5. 목적/세부 목적의 미충족 부분을 우선하며 포장 변형 후보를 묶고 최대3개를 고른다. 동률에는 목적 연결·가격·품번 등을 사용한다. 같은 제품군 판단은 표시 성분·제형·섭취법의 동등성 범위이며 전체 원재료 동일성 보장이 아니다.
6. 선택된 후보에 한해 Agent가 이유·확인할 점을 설명한다. 후보1~2개 또는 빈 결과도 정상 상태다.

품번 예시는 제한 없음·기존 없음 등 정해진 가상 조건의 개발 회귀 사례다. 누구에게나 필요한 제품이라는 뜻은 아니다. 자세한 제외/선정은 [정책 상세](../recommendation-policy-v2.md)를 따른다.

정량 중복은 확인 가능한 하루 기준과 단위만 합산한다. g/mg/μg 질량 환산과 표시의 계산 가능성을 확인하며 IU·RAE·DFE·NE 등을 임의로 치환하지 않는다. 비교표는 같은 섭취 기준과 단위가 확인되어야 함량의 차이를 다룬다. 미확인을0으로 취급하거나 표시 합계로 병용 안전성을 판단하지 않는다.

## AI 비교 해설

[comparison.py](../../backend/comparison.py)는 표시 비교 사실과 근거 ID를 구성한 뒤 GPT에 요약·핵심 차이·선택 기준을 요청한다. 새로운 자율 Agent가 아니라 고정 생성 경로다. 양쪽 제품 출처·수치/표현 범위를 검사하고, 실제 숫자·기준은 서버 제공 사실 영역에서 보여준다. 원재료 전체 동일·효능 우위·높은 함량이 더 좋다는 추론을 금지한다.

동일 비교의 완료 결과는 프로세스 메모리에1시간·최대128개 캐시한다. 같은 생성 요청은 합치고 대기 키는 최대8개다. 캐시 검사는 실제 모델 생성 반복 횟수와 분리해 기록한다. 실패해도 공개 표시표는 유지한다.

## 메모리·개인정보·한계

사용자 장기 메모리는 없다. 화면 대화 이력은 최근 최대8개를 입력 계약으로 받으며, 민감한 사용자 턴과 이어진 응답을 외부 이력에서 제거하고 안전한 최근 최대6개 턴으로 줄인다. 외부 설문에는 관심·예산·제형만 전달하고 주의조건·식습관·기존 제품 목록은 제외한다. 민감/긴급 질문은 [privacy.py](../../backend/privacy.py)에서 로컬 분기한다. `store=False`를 보내지만 COPA/모델 제공자의 보존 정책까지 무보존으로 보장하지 않는다.

키워드 기반 검색은 표현 변화에 취약하고, 정규식·스키마 검증은 모든 의미 오류를 막지 못한다. 현재 원문 대조는 독립 임상 검증이 아니며 추천은 소규모 규칙의 제품 탐색 보조다. 실사용자 평가를 통한 성능·편의성 효과는 [피드백 증빙](user-feedback.md) 보완 후 판단한다.

## 후속 로컬 개선 — 성분 요약의 숫자와 설명 분리

제품의 주요 성분 질문에는 [product_summary.py](../../backend/product_summary.py)가 검수 DB의 성분명·함량·단위·등호/부등호·섭취 기준을 `nutritionSummary`로 제공한다. 원래 표시의 `percent`는 원문 값으로 보존한다. 화면의 새 비율은 [공식 성인 기준](../adult-intake-reference.md)의 성별·연령별 권장섭취량 또는 충분섭취량과 비교해 검증 함수로 계산한다. 모델은 숫자를 생성하지 않는다. 하루 분량·단위·공식 기준을 확인할 수 없으면 계산하지 않고, 총내용량·여러 정 기준을 임의로 바꾸지 않는다. 비교 기준 선택은 브라우저에서만 사용한다.

Agent는 기능/영양 근거를 우선 사용해 성분 역할만 짧고 쉬운 두세 문장으로 설명한다. 본문에는 질문과 무관한 긴 주의 문구를 반복하지 않는다. UI는 함량·선택한 성인군의 RNI/AI 대비 비율 표를 먼저, 쉬운 설명을 다음에 표시하고 공식 기능·섭취법·주의·알레르기·출처를 접힌 상세 영역에 둔다. 보관/시간/주의 질문은 기존의 해당 주제 답변을 유지한다. [실제 로컬 GPT 검사](evidence/product-nutrition-overview-local.json)를 운영 기준 증빙과 구분한다.

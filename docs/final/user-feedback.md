# 사용자 피드백과 개선 기록

2026-10-24 · [제출 목차](README.md)

팀이 피드백·개선 항목으로 선정해 제공한 **사이트 주소, AI 질문 범위, AI 첫 질문 오류, 활력 추천 결과, 비슷한 제품의 중복 추천**을 정리했다. 아래 확인 질문과 피드백 요약은 팀이 제공한 개선 주제를 정리한 것이며 실제 참여자 발언의 직접 인용이 아니다. 변경 내용은 코드·커밋·운영 검증을 근거로 작성했다.

테스트 날짜는 팀이 전달한 기준에 따라 **2026-10-22에2건, 2026-10-23에3건**으로 기입했다. 참여자 표는 요청에 따라 다섯 개선 항목을 T1~T5 순서로 배치한 팀 제공 정리본이다. 실제 참여자별 타깃 근거와 응답 원본은 별도 확인이 필요하며, 개발자 QA는 실사용자 수에 포함하지 않는다.

## 선정한 5개 개선 항목

| 항목 | 불편을 확인하는 질문 | 개선 전 → 개선 후 | 사용자가 체감할 변화 | 실제 변경·확인 근거 |
|---|---|---|---|---|
| F01 사이트 주소 | 사이트 주소만 보고 어떤 서비스를 제공하는 곳인지 알 수 있었나요? | `m2-1-itfc.onrender.com` → `vitastep-guide.onrender.com` | 영양제 안내 서비스라는 인상을 주고 다시 찾거나 공유할 때 식별하기 쉬움 | [주소 변경1e44b76](https://github.com/sayknow/M2-1/commit/1e44b76), [운영 URL](https://vitastep-guide.onrender.com/) |
| F02 AI 질문 범위 | 제품 정보 외에 성분의 역할·식사·보관 등 일반적인 영양제 질문에도 답변받을 수 있었나요? | 제품 표시 검색 중심 → 공식 일반 영양 지식과 표시 검색을 구분하는 상담 안내 | 제품을 선택하기 전에도 일반 영양 정보를 묻고 출처를 확인할 수 있음 | [상담 개선b1185bf](https://github.com/sayknow/M2-1/commit/b1185bf), [AI 설계](ai-design.md) |
| F03 AI 첫 질문 오류 | 첫 질문인 ‘함량과 기준량의 차이가 궁금해요’를 선택했을 때 오류 없이 설명을 받을 수 있었나요? | 상품 근거만 찾다가 `AI_NO_EVIDENCE` → 제품 선택 없이 표시 읽기 안내 검색·인용 | 첫 질문에서 용어 설명을 바로 받고 질문을 시작할 수 있음 | [수정c8fa914](https://github.com/sayknow/M2-1/commit/c8fa914), [운영 M03 3/3](evidence/acceptance-api.json) |
| F04 활력 추천 결과 | ‘일상의 활력’을 선택했을 때 예상한 목적에 맞는 제품이 추천되고 그 이유를 이해할 수 있었나요? | 넓은 성분 연결 → B 중심 직접 목적 후보와 관련 성분을 분리, 표시상 근거 제시 | 선택한 관심과 후보 이유의 연결을 이해하기 쉬움 | [분류b75f847](https://github.com/sayknow/M2-1/commit/b75f847), [PR #4](https://github.com/sayknow/M2-1/pull/4), 운영 대표 사례2/3 |
| F05 비슷한 제품 중복 추천 | 추천 목록에 용량이나 포장만 다른 비슷한 제품이 반복되어 선택이 어렵지는 않았나요? | 비슷한 변형을 나열 → 표시 성분·제형·섭취법 기준 제품군을 묶어 대표 후보, 미충족 목적 우선 | 같은 종류를 반복해서 읽는 부담이 줄고 후보 간 차이를 살펴보기 쉬움 | [분류b75f847](https://github.com/sayknow/M2-1/commit/b75f847), [정책 상세](../recommendation-policy-v2.md), [정책 코드](../../backend/policy.py) |

‘체감할 변화’는 개선으로 기대하는 사용상 효과다. 사용자 재평가로 측정한 만족도·시간 단축률은 아니다. F04는 개인에게 B군이 반드시 필요하다는 판단이 아니라 제품 탐색 목적 분류 개선이다. F05의 포장 변형 중복과 기존 섭취 제품의 성분 중복 검사는 별개의 기능이다.

## 현재 증거로 말할 수 있는 범위

- 위 다섯 변경은 실제 코드/배포에 반영되었다. 운영 배포 기준은 `0bc17dc`다.
- 공식 표시를 근거로 추천 후보를 바꾸고 첫 질문을 실제 GPT로 확인한 기술 기록이 있다.
- 테스트 날짜와 요약은 팀 제공 정보를 반영했다. 실제 참여자의 발언·개선 후 평가는 응답 원본과 대조해야 한다.
- G5 완료를 위해 **팀원 제외 최소5명의 실제 타깃 이용과 응답 원본**을 추가해야 한다. 다른 팀 교육생도 서비스 타깃에 해당하는 근거가 있을 때만 포함한다.

## 참여자 등록 표

테스트 날짜는 팀 제공 기준이며, 확인 질문은 위5개 개선 항목의 불편을 질문형으로 바꾼 것이다. 피드백 요약은 앞서 제공된 개선 주제를 정리했다. 참여자의 직접 인용이나 개선 후 재평가 결과로 표현하지 않는다.

| 가명 | 테스트 날짜 | 확인 질문 | 피드백 요약(팀 제공) |
|---|---|---|---|
| T1 | 2026-10-22 | 사이트 주소만 보고 어떤 서비스를 제공하는 곳인지 알 수 있었나요? | 과제 코드가 들어간 주소로는 서비스의 목적을 파악하기 어려움 |
| T2 | 2026-10-22 | 제품 정보 외에 성분의 역할·식사·보관 등 일반적인 영양제 질문에도 답변받을 수 있었나요? | 제품 정보에 한정된 답변으로 일반적인 영양제 궁금증을 해결하기 어려움 |
| T3 | 2026-10-23 | 첫 질문인 ‘함량과 기준량의 차이가 궁금해요’를 선택했을 때 오류 없이 설명을 받을 수 있었나요? | 시작 질문에서 근거 없음 오류가 나타나 대화를 시작하기 어려움 |
| T4 | 2026-10-23 | ‘일상의 활력’을 선택했을 때 예상한 목적에 맞는 제품이 추천되고 그 이유를 이해할 수 있었나요? | 마그네슘·일부 멀티비타민 등 예상과 다른 후보가 나와 추천 이유를 납득하기 어려움 |
| T5 | 2026-10-23 | 추천 목록에 용량이나 포장만 다른 비슷한 제품이 반복되어 선택이 어렵지는 않았나요? | 비슷한 포장 변형이 반복되어 후보 간 차이를 느끼기 어려움 |

테스트 날짜와 코드 반영일은 구분한다. 일부 수정 커밋은 위 테스트 날짜보다 앞서므로, 이 표를 모든 수정이 해당 테스트 이후에 이루어졌다는 근거로 사용하지 않는다.

원본 확보 시 항목별로 참여 가명·발생일·실제 질문/응답·수정 커밋·재확인 결과를 연결한다. 반영하지 않은 의견도 이유를 적는다. 인터뷰/설문 화면의 이름·연락처·계정·개인 건강정보는 가리고 `docs/final/evidence/` 안에 마크다운 또는 PDF로 추가한다. 원본의 실제 날짜를 작성일로 덮어쓰지 않는다.

## 실사용자 확인 질문

1. 사이트 주소와 첫 화면을 보고 어떤 서비스인지 설명할 수 있었나요?
2. 설문을 혼자 완료할 수 있었나요? 이해하기 어려운 선택지는 무엇이었나요?
3. 추천 이유와 후보 간 차이를 이해할 수 있었나요? 비슷한 제품이 반복됐나요?
4. ‘함량과 기준량’ 시작 질문과 직접 작성한 일반 성분 질문에 답변·출처를 받을 수 있었나요?
5. 비교 해설·표에서 고르는 데 도움이 된 정보와 부족한 정보는 무엇이었나요?
6. 오류·정보 부족 안내가 나왔을 때 다음 행동을 알 수 있었나요?

실제 질환·복용약·검사 수치를 묻지 않는다. 원본을 받기 전에는 위 질문에 대한 응답이나 개선 후 만족도를 대신 작성하지 않는다.

# 영양제 첫걸음 UI 설계 및 구현

2026-10-20. 모바일 360~430px 우선, 데스크톱 1280~1440px 대응. 서비스 제목은 **영양제 첫걸음**, 보조 문구는 **다이소 영양제, 쉽게 고르고 비교하기**다. 실제 추천·AI 기능은 다음 백엔드 단계에서 연결한다.

## 화면 구성·주요 행동·이동

| 화면/경로 | 정보 배치 | 버튼·이동 | 오류·정보 부족 |
|---|---|---|---|
| 홈 `#/` | 짧은 소개·주CTA → 체험 안내 → 제품 카드 → 3단계 이용 흐름 → 표시 읽기 | 질문에 답하고 찾아보기 → 설문, 제품 찾기 → 라이브러리, 예시 보기 → 결과, AI 대화 | 제품을 맞춤 추천으로 표시하지 않음. 실물 사진 대신 일러스트임을 표시 |
| 안내/동의 `#/survey/1` | 목적·체험 범위 → 임시 정보 처리 → 필수 확인 2개 | 확인하고 시작하기, 먼저 제품 둘러보기 | 동의 전 단계 진행 차단·인라인 오류. 새로고침하면 동의·설문 초기화 |

| 상세 `#/products/:id` | 일러스트 → 유형·포장·관찰가 → 주요 성분과 기준 → 섭취법 → 주의·알레르기·보관 → 전체 원료/출처 | 목록, 비교 담기/빼기, 이 제품 질문하기, 공식 출처 새 탭 | 없는 품번·보류 품번은 찾을 수 없음. 정량 정보 부재는 0과 구분. 주요 주의사항은 접지 않음 |
| 비교 `#/compare` | 두 제품 슬롯 → 검색/추가·교체 → 기준 안내 → 항목별 두 값 | 선택·해제·교체, 차이만 보기, 상세, 제품 질문 | 2개 미만 안내, 세 번째 선택 시 교체 모달, 표시 정량 없음·기준 차이·비용 계산 미제공 |

홈부터 설문·결과·상세·비교·대화가 이어지며, 비교와 대화는 홈에서 바로 시작할 수도 있다. 해시 URL을 사용해 정적 서버에서도 직접 접근과 뒤로가기가 가능하다. 탭 안에서는 React 상태가 유지되고 새로고침하면 메모리 상태가 사라져 안전한 초기 화면으로 돌아간다.

## 디자인과 편의

- 주조색 `#df2636`, 흰 카드, 따뜻한 옅은 회색. 실제 다이소 로고는 사용하지 않고 4칸 모양의 독립 브랜드 마크를 만들었다.
- 가격은 굵게, 기준·단위는 가까이 배치. 어려운 성분명보다 ‘무엇을 확인하는지’를 먼저 설명한다. 적합도 점수나 효능 보장을 사용하지 않는다.
- 모바일 홈의 소개 이미지는 생략하고 제품 카드를 이용 안내보다 앞에 배치해 첫 행동과 제품 탐색이 빠르게 보이도록 했다. 데스크톱은 4열 카드, 모바일은 2열이다.
- 모바일 하단 홈·추천받기·비교하기·AI 대화. 제품 탐색·결과·상세에서 제품 선택 중인 경우 별도 비교 바와 하단 여백. 설문·AI 대화에서는 비교 바를 숨기고 메뉴 배지와 선택 상태만 유지한다. 긴 화면의 입력·버튼이 가려지지 않도록 문서 하단에도 여백을 둔다.
- 비교는 모바일에서 항목 제목 아래 두 값을 나란히 보여 가로 스크롤을 피한다. 같은 기준으로 확인하지 않은 수량을 자동 환산하지 않는다.
- 체크·선택은 색 외 아이콘·문구·`aria-pressed`로도 표현한다. 버튼 44px 내외, 주요 CTA 46~48px. 본문 바로가기·키보드 포커스·레이블·실시간 오류 알림·모달 기본 초점·Escape 취소를 지원한다.
- 제품 일러스트는 CSS로 직접 그렸다. 원본 성분표를 썸네일에 축소해서 넣거나 실물 포장 사진이라고 표시하지 않는다.
- 실제 건강정보를 받지 않는 체험용 선택지. localStorage·쿠키·서버 저장 없이 메모리 상태만 사용한다. 채팅에도 실제 진단명·약품명·개인정보를 적지 않도록 안내한다.

## 재현 가능한 상태

검증용 선택기는 기본 화면에 노출하지 않는다. 아래 재현 URL 또는 `#/results?state=example&preview=1`에서만 상태 선택기를 확인한다. 정상 흐름에 무작위 오류를 넣지 않는다.

- `#/results?state=example`: 고정 3후보
- `#/results?state=loading`: 약 0.7초 후 고정 예시 표시
- `#/results?state=empty`: 결과 없음
- `#/results?state=insufficient`: 기존 제품 등 정보 부족
- `#/results?state=restricted`: 전문가 확인이 필요한 제한 상태 표현
- `#/results?state=error`: 호출 실패, 다시 불러오기

`#/chat?preview=1`의 ‘대화 오류 상태 체험’에서 체크 후 질문하면 한 번 실패하고 같은 질문으로 재시도할 수 있다. 이 메뉴는 체험 상태를 의도적으로 확인하는 경로다. 주의조건에 따른 실제 추천 허용·제한을 계산한 결과가 아니다.

## 제품 데이터 경계

검수 데이터 원본은 보존한다. 화면용 정적 JSON에는 전체 87개 완료 제품의 필요한 직접 검수값만 넣는다. 보류 1개와 원본 OCR·출처 이미지 전체·추출 후보·내부 검수 이력은 포함하지 않는다. 각 제품에 공식 URL·표시 관찰일·검수일·가격 관찰일이 있다. 일반식품도 실제 유형을 유지한다.

주요 성분은 표시 영양표에서 일반 열량·3대 영양소 등을 뺀 정량 행이다. 개인별 효과나 적합도 순위가 아니다. 영양정보가 표시되지 않은 경우에는 미표시로 안내한다. 전체 영양정보 펼침에 원래 정량 행을 보여 준다.

## 후속 API 경계

`SelectionService.examples(survey)`와 `.reply(question, context)`는 현재 `mockService`가 담당한다. 이후 별도 HTTP 어댑터로 교체할 수 있도록 화면과 인터페이스를 분리했다. 현재 단계에서는 실제 Agent·RAG·Gemini 호출·추천 규칙·중복 검사·일일 비용 계산을 구현하지 않는다.

후속 FastAPI에서는 검수 완료 제품만 반환하는 상품 조회·검색, 추천 후보+근거+제한 상태, 성분 기준을 보존한 비교, 대화 세션/인용 근거를 제공해야 한다. 서버 검증·전송 동의·상태코드·오류/재시도·취소 정책을 API와 함께 확정해야 한다. API 키는 프런트 코드에 포함하지 않는다.

가격 확인일은 원본 카탈로그 관찰일(2026-10-19), 표시정보 검수일은 각 제품의 실제 label review 날짜로 구분한다. 자료 날짜를 현재 날짜로 일괄 갱신하지 않는다.

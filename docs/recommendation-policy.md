# 추천 정책 v2026-10-21.1

현재 프런트엔드의 5단계 설문을 그대로 입력 계약으로 사용한다. 일반 성인이 공식 제품 표시를 이해하고 후보를 좁히는 정보 서비스이며, 개인별 결핍·효과·병용 안전성이나 의료적 적합성을 판정하지 않는다.

## 입력과 처리

| 입력 | 처리 |
|---|---|
| 관심 분야 | 검수된 **기능정보 원문**과 연결한다. 활력→에너지, 뼈·근육→뼈/근육, 장→배변/유익균, 눈→눈/시각/황반. ‘다양한 성분 보기’는 표시 기능성·영양 성분 3개 이상인 제품을 탐색한다. |
| 식습관 | 요약에 반영하되 영양 결핍이나 필요한 성분을 추정하지 않는다. |
| 기존 제품 | 검수 제품 최대 10개. 표시 영양·기능성 성분의 중복을 확인하고, 같은 성분이 있는 새 제품은 자동 후보에서 제외한다. |
| 주의조건 | 의약품 복용·치료, 임신·수유, 알레르기 확인 필요는 추천 제한. ‘모름’은 추가 확인 상태. |
| 예산 | 관찰 당시 단품 가격에 3,000원/5,000원 상한을 적용한다. 실시간 가격·재고가 아니다. |
| 제형 | 직접 검수한 제형이 선택한 그룹에 속하는 경우만 통과한다. 미확인은 일치로 추정하지 않는다. |

관심 분야·기존 제품·주의조건이 불명확하면 후보를 만들지 않고 해당 설문 단계로 연결한다. 식습관의 ‘모름’은 진단에 쓰지 않으므로 그대로 진행할 수 있다. 입력의 허용값·배타 선택·제품 ID·동의는 서버에서도 검증한다.

## 제품 후보 범위

1. DB의 표시 검수 완료 제품만 읽는다. 보류 품번 `600651654`는 상품 조회·비교·추천에서 제외한다.
2. 일반식품은 표시 정보 탐색·비교만 제공하며 자동 추천 후보에는 넣지 않는다.
3. 기능정보·섭취방법·주의사항·정량 근거가 있어야 한다. 정량 기준은 원문에 하루 섭취량이 명시되어 있어야 한다.
4. 키즈·임산부·성별 특화·월경·전립선·철분·체중감량·혈당·혈압·수면·갱년기 등 추가 조건이 필요한 제품은 초기 일반 선택 범위에서 제외한다. 상품명뿐 아니라 표시 기능정보에 혈당·혈압·질 건강·간 건강 등 특화 기능이 있는지도 확인한다. 현재 설문에 없는 연령·성별·검사 결과를 추측하지 않는다.
5. 표시 영양성분 기준치 비율이 200%를 초과하거나 해당 비율을 해석할 수 없는 제품은 초기 자동 후보에서 제외한다. **이 200%는 프로젝트의 보수적인 제품 탐색 범위이며, 의학적 상한섭취량·안전 기준이 아니다.** 비율 미표시는 0으로 대입하지 않는다.
6. 기존 제품과 같은 표시 성분이 있는 제품 및 사용자가 이미 고른 제품은 추가 후보에서 제외한다.

조건을 통과한 뒤 연결되는 관심 분야 수, 관찰 가격 오름차순, 품번 순서로 정렬한다. 높은 함량·질병 개선·임상 효과나 적합도 백분율로 순위를 매기지 않는다. 최대 3개이며 이 후보들을 함께 모두 섭취하라는 의미가 아니다. 조건을 만족하는 제품이 없으면 빈 결과를 그대로 안내한다.

제품별 판단은 `backend/policy.py`의 `exclusion()`과 `recommend()`에서 재현할 수 있다. 기존 원본 DB의 `recommendation_eligible=false`는 수집 당시 미평가 기록으로 보존한다. 현재 서비스 후보 판정은 이 버전의 별도 정책으로 계산하며, 개인의 의료적 적합성을 검수 완료 상태로 승격하지 않는다.

## 중복 검사와 정량

- 표시 영양·기능성 성분을 대상으로 하며 일반 열량·당류·단백질 등을 제외한다. 원재료 목록 전체의 상호작용 검사가 아니다.
- 공백 표기를 정리하고 셀레늄/셀렌 등 명시한 동의어만 연결한다. 비슷해 보인다는 이유로 다른 물질을 합치지 않는다.
- 같은 제품 안의 같은 성분은 중복 제품으로 세지 않는다.
- 원문에서 하루 기준을 확인하고 수량이 정확한 `=`인 경우만 합산한다. `<`, `<=`, `>=`는 합산하지 않는다.
- 같은 성분의 g/mg/μg만 질량 단위로 환산한다. IU·CFU·RAE·DFE·NE·α-TE 등은 다른 단위와 자동 변환하지 않는다. 동일 단위와 하루 기준이 확정된 경우에만 같은 단위 내 합산한다.
- 총내용량·기준 불명·단위 불일치는 중복 존재만 표시하고 합계를 미확인으로 둔다. 미확인을 0이나 안전으로 처리하지 않는다.
- 식사·의약품·미등록 제품은 검사에 포함하지 않는다. 식이 섭취량을 모르는 상태에서 상한 초과·미초과를 판정하지 않는다.

## AI 역할과 근거

서버가 후보·제한·계산을 결정한다. Gemini는 도구를 선택해 표시를 검색하고 선택 근거를 설명한다. 도구는 상품 검색, 상세 조회, 근거 검색, 중복 상태 확인, 비교, 정책 추천 조회, 일반 영양 지식 검색이다. API의 함수 실행과 인자 검증은 서버에서 수행한다.

RAG는 요청마다 SQLite의 직접 검수 필드를 검색하고 필드 ID·공식 URL·원문·관찰일을 모델에 전달한다. 최종 인용은 실제 조회한 ID만 허용하며 URL은 서버가 붙인다. 추천 설명의 제품과 출처는 선정 후보 내로 제한한다. 모델이 용량 수치를 생성하게 하지 않으며 B12·오메가3 등 성분명 숫자는 구별한다. 정량·섭취방법은 화면의 검수 원문으로 확인하게 한다. 원문과 구별되는 용량 지시·진단·효과 보장을 허용하지 않는다.

개인별 의료 판단이나 개인정보 형식은 로컬 검사로 제한한다. 일반적인 성분·섭취·상호작용 원리 질문은 공식 지식으로 설명할 수 있다. 이는 임의의 모든 민감정보를 완벽하게 식별하는 시스템이 아니므로 사용자에게 실제 개인정보·진단명·개인 복용 내역을 입력하지 않도록 안내한다. 모델 오류·지연·미설정은 명시하고 고정 예시를 실제 AI 응답으로 대체하지 않는다. 추천 정책은 유지하며 일반 지식 상담의 확장은 [AI 상담가 문서](ai-counselor.md)를 참고한다.

## 참고한 공식 자료와 적용 범위

- [현재 검수 DB와 공식 표시 출처](product-database.md): 실제 제품의 기능정보·단위·섭취법·주의사항 근거. 관심과 제품을 연결하는 직접 근거는 각 제품의 인용 필드다.
- [NIH ODS 마그네슘 자료](https://ods.od.nih.gov/factsheets/Magnesium-Consumer/): 영양소 역할·표시와 개인별 필요량·상호작용 판단을 구분하는 배경 자료. 미국 기준 섭취량을 한국 사용자 정책의 수치 기준으로 옮기지 않았다.
- [NIH ODS 영양보충제 안내](https://ods.od.nih.gov/factsheets/DietarySupplements-Consumer/): 보충제의 역할과 제품 표시를 이해하는 배경 자료. 질환 치료를 위한 추천 정책으로 사용하지 않았다.

사용자 피드백은 질문의 이해도·설명·선택 편의 개선에 사용하고, 효능·용량·안전 기준을 사용자 선호만으로 변경하지 않는다.

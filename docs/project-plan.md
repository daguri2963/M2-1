# 프로젝트 기획서 — 영양제 첫걸음

최종 정리: 2026-10-24 · 구현 기준: `0bc17dc` · [제출 문서 목차](final/README.md)

## 문제와 타깃

타깃은 영양제를 처음 구매하거나 제품 표시를 읽는 데 어려움을 느끼는 **일반 성인**이다. 접근하기 쉬운 다이소 제품으로 시작하려 해도 비슷한 제품이 많고, 성분·함량·기준량의 의미를 이해하기 어렵다. 어떤 후보부터 살펴볼지, 두 제품이 어떻게 다른지, 현재 제품과 성분이 겹치는지 확인하는 과정에도 부담이 있다.

이는 팀이 정한 문제 가설이다. 대상 인구의 규모나 만족도·건강 효과를 입증한 조사 결과는 제시하지 않는다. 목표는 구매 전 **정보 이해와 후보 탐색을 돕는 것**이다.

## 해결 방식과 사용자 흐름

홈에서 `추천받기`, `제품 찾기`, `비교하기`, `AI에게 물어보기`로 이동한다. 처음 고르는 사용자는 5단계 설문으로 후보를 보고 이유와 출처를 확인한 뒤 상세·비교·대화로 이어간다. 이미 제품을 아는 사용자는 설문 없이 목록·상세·표시 비교를 이용한다.

| 경험 | 실제 구현 | 사용자 가치 |
|---|---|---|
| 설문 후보 추천 | 관심·기존 제품·주의조건·예산·제형에 따라 최대 3개 | 전체 목록을 읽기 전 탐색 범위를 줄임 |
| 제품 찾기·상세 | 공식 사진·관찰 가격·규격·성분·정량·섭취법·주의·출처 | 흩어진 표시를 같은 형식으로 확인 |
| 두 제품 비교 | 표시 비교표와 선택적 AI 차이 해설 | 기준이 다른 숫자를 단순 우열로 오해하지 않도록 도움 |
| AI 대화 | 공식 영양 지식·검수 제품 검색과 출처 설명 | 제품 선택 전 용어·일반 영양 정보를 질문 |

모바일을 우선하고 빨강·흰색의 친숙한 제품 탐색 분위기를 사용한다. 비제휴 학습 서비스임을 명시한다. 정보 부족·추천 제한·서버 준비·AI 실패를 구분해 보여준다.

## 범위와 목표

- 관심 분야는 **일상의 활력, 뼈·근육 건강, 장 건강, 혈당 관리, 다이어트**이며 복수 선택한다.
- 일반 성인의 제품 선택 보조와 제품 표시 섭취방법 안내까지 제공한다. 개인별 복용량 결정·진단·치료·병용 안전성 확정은 제공하지 않는다.
- 핵심 Must는 8개다. AI 비교 해설은 Should다. 외부 상위 대안, 로그인, 장기 기록, 눈 건강 추천, 실시간 가격·재고, 사진 분석은 현재 범위 밖이다.
- 혈당·다이어트는 검토된 표시와 범위 확인을 거친 후보만 사용한다. 진단·치료·의약품, 임신·수유, 알레르기 확인이 필요한 경우 개인 추천을 제한한다.
- 최소 5명의 실제 타깃에게 제공하고 피드백을 수집·반영하는 것이 과제 목표다. 개선 기록과 참여자 증빙 상태는 [피드백 문서](final/user-feedback.md)에 구분한다.

## 데이터 확보와 품질

다이소몰 공식 상품 상세·제조사 표시자료를 근거로 88개 SKU를 수집했다. 공식 라벨 원문·OCR·검수 값·정정 이력을 구분하고 URL·원본 파일 해시·관찰일을 보존했다. 공개 가능한 검수 상품은 87개다. 유산균 정량을 확인하지 못한 `600651654`는 보류했다. 공식 썸네일 88개 중 공개 87개 제품에 사진을 연결했다.

정량에는 수치·단위·섭취 기준·등호/부등호를 보존한다. 미확인 값을 0으로 바꾸지 않는다. 자동 판독 후 같은 에이전트가 원문을 대조했으며, 독립 제2검수나 임상 검증을 받은 자료는 아니다. [DB 설명](product-database.md)·[라벨 검수](product-label-review.md)를 근거로 한다.

## 기술적 접근과 선택 이유

| 구성 | 최종 선택 | 선정 근거 |
|---|---|---|
| 화면 | React·TypeScript·Vite | 모바일 UI, 타입 기반 API 연결, 정적 배포 |
| 서버 | Python·FastAPI | 데이터 처리 언어 재사용, 입력 검증, 비동기 AI 요청 |
| DB | 읽기 전용 SQLite | 88개 규모에 별도 DB 서버 없이 검수 DB 배포 |
| 추천 정책 | 검수 표시 + 버전 관리 분류 JSON | 후보·제외 이유 재현, GPT 임의 제품 선택 방지 |
| AI Agent | OpenAI Python SDK → COPA → `gpt-5.4` | 코디세이 인증·도구 호출의 실제 호환성 검증 |
| RAG | 질의별 SQLite·공식 지식 카드 검색 | 표시·출처를 동적으로 찾아 답변에 반영 |
| 배포·검사 | Render 정적 사이트 + Docker API, GitHub Actions | 소규모 운영, 로컬 확인 후 승격 |

인정 대상은 **AI Agent와 RAG**다. 모델이 여러 도구 중 실행 대상을 정하고 검색 결과를 사용한다. 후보 선정은 결정적 규칙으로 수행하고 AI는 근거를 설명한다. 벡터 DB·임베딩·학습은 사용하지 않는다. 초기 Gemini에서 COPA GPT로 바꾼 과정은 [AI 설계](final/ai-design.md)에 기록한다. 초기 Next.js·PostgreSQL·pgvector 제안은 최종 채택하지 않았다.

## 역할과 협업

이승현은 **주 개발**, 조준수는 **부 개발**로 프런트·백엔드·AI 추천 개발을 함께 담당하는 배정이다. 김재욱은 자료 수집·검수와 RAG 자료, 윤준서는 기획·요구 명세, 배창민은 테스트·피드백·진행 문서로 배정한다. 세부 역할 배정과 실제 수행 증빙은 [팀 기여 문서](final/team-contributions.md)에서 구분한다.

`sayknow`는 이승현 계정이다. `main`은 초기 프로토타입을 보존하고 `canary → dev → production`으로 승격한다. canary에서 로컬 확인 후 CI를 거쳐 dev에 병합하고 주 관리자가 production 반영을 관리한다. 별도 Render 시험 서버는 운영하지 않는다.

## 성공 기준과 한계

Must 8개가 각각 3회 중 2회 이상 기대 결과를 내고, 외부 서비스에서 Agent·RAG가 동작하며, 실제 타깃 5명 피드백과 전원 기여 증빙이 연결되어야 한다. 발표 PDF도 필요하다. 기술 검사는 해당 기준에 도달했지만 추천 AI 검증 1회 실패가 있었고, 실사용자 원본·전원 개인 기여·PDF는 별도 보완 대상이다.

작은 상품 범위, 오래될 수 있는 가격·표시, 외부 AI 장애·사용량 제한, 규칙/응답 검증의 한계를 안내한다. 현재 결과로 영양 결핍·건강 개선·개인 적합성을 입증하지 않는다.
